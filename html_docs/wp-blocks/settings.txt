<!-- wp:heading {"level": 1} -->
<h1 class="wp-block-heading">Canvasly settings</h1>
<!-- /wp:heading -->

<!-- wp:paragraph {"className": "lede"} -->
<p class="lede">Open <strong>Canvasly</strong> in the WordPress admin menu. Most site options are under Settings. Colors and screen sizes are under Design System. Who may edit is under Role Manager. Which units appear is under Units Manager.</p>
<!-- /wp:paragraph -->

<!-- wp:paragraph {"className": "meta"} -->
<p class="meta">Updated <time datetime="2026-09-22">September 22, 2026</time>. Covers Canvasly 0.12.76 and Canvasly Pro 0.6.3.</p>
<!-- /wp:paragraph -->

<!-- wp:heading {"level": 2, "anchor": "performance"} -->
<h2 class="wp-block-heading" id="performance">Settings &#8594; Performance</h2>
<!-- /wp:heading -->

<!-- wp:paragraph -->
<p>The fragment cache stores the HTML of units that do not use dynamic tags. Lazy load waits to load background images below the first one and marks the first image to load sooner. Optimized markup removes an extra wrapper when a unit already has a single outer element.</p>
<!-- /wp:paragraph -->

<!-- wp:html -->
<table>
        <thead><tr><th>Option</th><th>Default</th><th>What it does</th></tr></thead>
        <tbody>
          <tr><td>Unit cache</td><td>On</td><td>Cache HTML for units that are not dynamic.</td></tr>
          <tr><td>Cache TTL (hours)</td><td>24</td><td>How long a cached fragment is kept. The screen allows 1 to 168 hours. The stored default is 86,400 seconds, which is 24 hours.</td></tr>
          <tr><td>Lazy load</td><td>On</td><td>Background images after the first one load later. The first image uses fetchpriority high. Later images use loading lazy.</td></tr>
          <tr><td>Optimized markup</td><td>Off</td><td>Remove the extra node wrapper on simple units when it is safe.</td></tr>
        </tbody>
      </table>
<!-- /wp:html -->

<!-- wp:paragraph -->
<p><strong>Flush unit cache</strong> clears those stored fragments.</p>
<!-- /wp:paragraph -->

<!-- wp:heading {"level": 2, "anchor": "tools"} -->
<h2 class="wp-block-heading" id="tools">Settings &#8594; Tools</h2>
<!-- /wp:heading -->

<!-- wp:paragraph -->
<p>The same jobs are also on <strong>Canvasly &#8594; Tools</strong>. Regenerating CSS, replacing URLs, and kit import or export use those tools.</p>
<!-- /wp:paragraph -->

<!-- wp:heading {"level": 3} -->
<h3 class="wp-block-heading">Regenerate CSS</h3>
<!-- /wp:heading -->

<!-- wp:paragraph -->
<p>Rebuilds the global stylesheet and every document CSS file. Use it after a move, a breakpoint change, or if styles look out of date. There is no stored default; it runs when you press the button.</p>
<!-- /wp:paragraph -->

<!-- wp:heading {"level": 3} -->
<h3 class="wp-block-heading">Replace URL</h3>
<!-- /wp:heading -->

<!-- wp:paragraph -->
<p>Rewrites a site address inside Canvasly documents and compiled CSS. The change cannot be undone. Run <strong>Dry run</strong> first. Both Old URL and New URL start empty and are required when you submit.</p>
<!-- /wp:paragraph -->

<!-- wp:heading {"level": 3} -->

<h2 class="wp-block-heading" id="roles">Role Manager</h2>
<!-- /wp:heading -->

<!-- wp:paragraph -->
<p><strong>Canvasly &#8594; Role Manager</strong> maps each WordPress role to Canvasly access. Administrators are always Full and cannot be lowered on this screen. A role that can edit posts or pages starts at Full. A role that cannot edit starts at No access.</p>
<!-- /wp:paragraph -->

<!-- wp:html -->
<table>
        <thead><tr><th>Access</th><th>What the person can do</th></tr></thead>
        <tbody>

        </tbody>
      </table>
<!-- /wp:html -->

<!-- wp:heading {"level": 2, "anchor": "units-manager"} -->
<h2 class="wp-block-heading" id="units-manager">Units Manager</h2>
<!-- /wp:heading -->

<!-- wp:paragraph -->
<p><strong>Canvasly &#8594; Units Manager</strong> can turn a unit type off for the whole site, or hide it from a WordPress role. Usage counts come from saved documents. Nothing is disabled until you disable it. The Container unit is locked and cannot be disabled. A disabled type stays on existing pages so those pages still display; it is removed from the library for new inserts.</p>
<!-- /wp:paragraph -->

<!-- wp:heading {"level": 2, "anchor": "system-info"} -->
<h2 class="wp-block-heading" id="system-info">System Info</h2>
<!-- /wp:heading -->

<!-- wp:paragraph -->
<p><strong>Canvasly &#8594; System Info</strong> is a report for support: WordPress, the server, and Canvasly status. Secrets are left out. You can download the report. It does not change the site.</p>
<!-- /wp:paragraph -->

<!-- wp:heading {"level": 3} -->
<h3 class="wp-block-heading">Custom Code</h3>
<!-- /wp:heading -->

<!-- wp:paragraph -->
<p>CSS, and HTML for the head or footer, print only where the display rule matches. HTML and JavaScript require the WordPress unfiltered_html capability. Accounts without it can still save CSS. A new snippet starts as CSS and published. Display can be limited with include and exclude rules. The code itself starts empty.</p>
